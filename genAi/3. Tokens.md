## 1. Tokens

_Tokens = Common, reusable sub-word chunks or characters converted into numerical IDs for computer execution._
- tokens are fundamental blocks that llm understands.

Plaintext

```
Natural Language Input
↓
Tokenizer Split (Sub-word/Common Chunks)
↓
Integer Token IDs
↓
LLM Execution
↓
Output Token IDs
↓
Detokenizer (Human-readable Text)
```

- Computers and LLMs cannot natively understand raw text; they only process numbers.
    
- Sub-word tokenization breaks down unknown/rare terms while storing common terms intact.
    
- Pricing for LLM APIs is based strictly on token counts, not character or word counts.
    

---

## 2. Token Approaches Evolution

_The transition from character-based and dictionary-word-based mapping to sub-word tokenization._

Plaintext

```
Character-based Mapping (Huge input sizes, bloated payload)
↓
Word-based Mapping (Fails on custom, rare, or misspelled words)
↓
Sub-word Tokenization / Tokens (Handles arbitrary vocabulary efficiently)
```

- Letter-level mapping inflates payload size drastically for small sentences.
    
- Whole-word mapping fails on custom names, typos, or slang not found in standard dictionaries.
    
- Tokens act like how children learn language—combining base words with reusable suffixes/prefixes.
    

---

## 3. Token Metrics & API Usage

_Tracking usage metrics for cost management and output control._

Plaintext

```
User Prompt
↓
Prompt Tokens (Input Cost)
↓
LLM Execution
↓
Completion Tokens (Output Cost)
↓
Total Tokens = Prompt Tokens + Completion Tokens
```

- `prompt_tokens` = Total tokens processed in the input prompt.
    
- `completion_tokens` = Total tokens generated by the LLM response.
    
- `total_tokens` = Combined input and output token count.
    
- `max_tokens` = Parameter that sets a hard upper limit on completion output length.
    
- `finish_reason` = Indicates if output finished naturally (`stop`) or was cut short (`length`).
    

---

## 4. Difference

| **Metric / Parameter** | **Function**                     | **Typical Finish Reason** |
| ---------------------- | -------------------------------- | ------------------------- |
| Prompt Tokens          | Measures input payload size      | N/A                       |
| Completion Tokens      | Measures model output size       | `stop` (natural end)      |
| Max Tokens Exceeded    | Hard truncates generation output | `length` (forced limit)   |

## 5. Code


```Python
import os
from dotenv import load_dotenv
from groq import Groq

load_dotenv()

client = Groq(api_key=os.getenv("GROQ_API_KEY"))

prompts = [
    "Hi",
    "Explain time travel in detail but under 100 words",
    "Write a 1000 word essay on Machine Learning"
]

for prompt in prompts:
    message = {
        "role": "user",
        "content": prompt
    }
    messages = [message]
    
    response = client.chat.completions.create(
        model="llama-3.3-70b-versatile", #change model
        messages=messages,
        max_tokens=50
    )
    
    usage = response.usage
    finish_reason = response.choices[0].finish_reason
    
    print(f"Prompt: {prompt}")
    print(f"Prompt Tokens: {usage.prompt_tokens}")
    print(f"Completion Tokens: {usage.completion_tokens}")
    print(f"Total Tokens: {usage.total_tokens}")
    print(f"Finish Reason: {finish_reason}\n")
```

## Interview Revision

- **What is a token in LLMs?**
    
    - _Answer:_ A token is a reusable chunk of text (word, sub-word, or character) represented as a numerical ID that an LLM uses to process and generate language.
        
- **Why is sub-word tokenization preferred over word-level or character-level mapping?**
    
    - _Answer:_ Character-level mapping results in excessively large input payloads, whereas word-level mapping fails on rare, misspelled, or out-of-dictionary terms; sub-word tokenization handles any arbitrary string efficiently with a compact vocabulary.
        
- **What is the difference between `prompt_tokens` and `completion_tokens`?**
    
    - _Answer:_ `prompt_tokens` represent the token count of the incoming input message, whereas `completion_tokens` represent the token count generated in the LLM's response output.
        
- **When would you set `max_tokens` in an API call, and what does `finish_reason: "length"` signify?**
    
    - _Answer:_ You set `max_tokens` to cap output length for cost control and latency prevention; a `finish_reason` of `"length"` signifies that generation was prematurely cut off by hitting this specified token cap rather than ending naturally (`stop`).
