## 1. Structured Outputs & Pydantic

_Guaranteed machine-readable LLM output formatting via type validation rules._


```
[Unstructured LLM Response] ---> (Pydantic Schema Validation) ---> [Strict JSON / Python Object]
```

- **Pydantic BaseModel**: Parent class defining schema type hints and validation logic.
    
      
    
- **Type Enforcement**: Ensures expected primitive types (`str`, `int`, `float`, `List`) at runtime.
    
      
    
- **JSON Schema Extraction**: Converts Python class definitions to standard JSON schema formats for LLM APIs.
    
      
    

---

## 2. Unstructured vs. Structured LLM Output

|**Unstructured Output**|**Structured Output**|
|---|---|
|Free-form text/markdown|Validated JSON object|
|Prone to unexpected formatting|Enforces defined schema|
|Requires fragile parsing regex|Direct instantiation to data models|

## 3. direct / easy code -

```Python
from pydantic import BaseModel, Field
from openai import OpenAI

client = OpenAI()

# Define strict target data model
class SupportTicket(BaseModel):
    user_name: str = Field(description="Name of the reporting user")
    email: str = Field(description="User contact email address")
    issue_description: str = Field(description="Detailed summary of reported issue")
    priority: str = Field(description="Assigned priority level: Low, Medium, High")

# Force model response into structured schema
response = client.beta.chat.completions.parse(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "Extract structured support ticket data from incoming customer messages."},
        {"role": "user", "content": "My name is Pratyush (pratyush@example.com). My phone screen is not working!"}
    ],
    response_format=SupportTicket
)

ticket: SupportTicket = response.choices[0].message.parsed
print(ticket.email)
print(ticket.issue_description)
```



### video code -

```python
import json
import os
from dotenv import load_dotenv
from openai import OpenAI
from pydantic import BaseModel, Field

load_dotenv()

client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))


# 1. Define the Pydantic schema
class Ticket(BaseModel):
    name: str = Field(description="Name of the person")
    email: str = Field(description="Email of the person")
    issue: str = Field(description="Issue of the person")
    address: str = Field(description="Address of the person")
    contact_number: str = Field(description="Contact number of the person")


# 2. Extract JSON schema dictionary manually from Pydantic model
schema = Ticket.model_json_schema()

# 3. Prompt setup
system_prompt = f"""
Extract the personal information from the ticket strictly based on this schema:
{json.dumps(schema)}
"""

text = "Hello My name is Pratyush. I have an iphone which is not working at all. My address is delhi. My email is abc@gmail.com. My contact number is 82134"

prompt = f"""
This is a customer ticket. Please extract the personal information from this.
{text}
"""

# 4. API Call using response_format="json_object"
response = client.chat.completions.create(
    model="gpt-4o-mini",
    response_format={"type": "json_object"},
    messages=[
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": prompt},
    ],
)

# 5. Manual Parsing of the returned JSON string
raw_content = response.choices[0].message.content      # String
ticket = Ticket.model_validate_json(raw_content)       # Pydantic Object

# direct

ticket_data = json.loads(raw_content) #python dictionary

print(ticket_data["name"])
print(ticket_data["email"])
print(ticket_data["issue"])

ticket = Ticket(**ticket_data); #pydantic object
print(ticket.name)
print(ticket.email)
print(ticket.issue)
```

## Interview Revision

- **What is Pydantic and why is it used in LLM applications?**
    
      
    
    _Pydantic is a data validation library that uses Python type hints to enforce schema constraints and reliably parse raw LLM text into type-safe objects._
    
      
    
- **How does `response_format` with Pydantic work under the hood in OpenAI API calls?**
    
      
    
    _It extracts the JSON Schema from the Pydantic `BaseModel` and enforces structured output sampling constraints on the LLM's token generation._
    
      
    
- **What is the difference between parsing manual JSON string responses and using Pydantic schema parsing?**
    
      
    
    _Manual JSON string parsing can fail due to invalid JSON syntax or missing key fields, whereas Pydantic schema parsing guarantees type correctness and key presence at runtime._
    
      
    
- **When would you use raw text responses vs structured Pydantic outputs?**
    
      
    
    _Use raw text responses for end-user chat interfaces, and use structured Pydantic outputs when the result feeds downstream API pipelines, databases, or programmatic logic._
    
      
    

### Golden Rule

> _Unstructured text is for human consumption; Pydantic-structured JSON is for programmatic reliability._

### The Two Approaches

When using Pydantic with OpenAI's API to get structured output, there are two distinct ways to pass the schema:


```Plaintext
Instructor Approach:
[Pydantic Model] ---> (.model_json_schema()) ---> [Raw JSON Schema Dict] ---> (system_prompt(specify to give json response) + response_format={"type": "json_object"}) ---> [Parse Raw String]

Direct Approach:
[Pydantic Model] ---> (response_format=PydanticModel) via client.beta.chat.completions.parse() ---> [Direct Python Object]
```

---

### Key Differences

|**Feature**|**Instructor's Approach (Manual JSON Schema)**|**Direct Approach (beta.chat.completions.parse)**|
|---|---|---|
|**Schema Generation**|Manually converts model via `.model_json_schema()`|Built-in (OpenAI client extracts it automatically)|
|**Response Format**|`response_format={"type": "json_object"}`|`response_format=SupportTicket`|
|**Prompt Injection**|Schema string must be injected into the system prompt|System prompt only describes the task|
|**Return Value**|Standard JSON string (requires `json.loads()`)|Direct Pydantic object (`response.choices[0].message.parsed`)|

---

### Detailed Code Breakdown of the Direct Version

Here is how each line works in the direct Pydantic parsing version:

  

#### 1. Defining the Schema

Instead of creating a manual JSON schema object, you define a standard Pydantic model.

  



```Python
class SupportTicket(BaseModel):
    user_name: str = Field(description="Name of the reporting user")
    email: str = Field(description="User contact email address")
    issue_description: str = Field(description="Detailed summary of reported issue")
    priority: str = Field(description="Assigned priority level: Low, Medium, High")
```

- `BaseModel`: Acts as the blueprint for the output.
    
      
    
- `Field(description=...)`: Replaces the need to explain schema properties manually inside your system prompt. OpenAI reads these descriptions directly from the class.
    
      
    

---

#### 2. Passing the Model to the API

Instead of extracting the schema dictionary using `Ticket.model_json_schema()` and setting `response_format={"type": "json_object"}`, you pass the class directly into `client.beta.chat.completions.parse`.


```Python
response = client.beta.chat.completions.parse(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "Extract structured support ticket data from incoming customer messages."},
        {"role": "user", "content": "My name is Pratyush (pratyush@example.com). My phone screen is not working!"}
    ],
    response_format=SupportTicket  # Pass class directly
)
```

- **Why no `model_json_schema()`?** The `.parse()` method calls `model_json_schema()` behind the scenes automatically.
    
      
    
- **Why no schema in system prompt?** Structured Outputs automatically forces the LLM's output grammar to match the schema defined in `response_format`, eliminating prompt leakage or syntax errors.
    
      
    

---

#### 3. Accessing the Data

In the instructor's method, the API returns a raw JSON string (`response.choices[0].message.content`), which you must deserialize manually using Python's `json.loads()`.

  

In the direct method, OpenAI parses and validates the response automatically:


```Python
ticket: SupportTicket = response.choices[0].message.parsed

print(ticket.email)             # Access attributes directly with dot notation
print(ticket.issue_description)
```

- `message.parsed`: Returns a fully instantiated `SupportTicket` object. If the LLM output violates the schema (e.g., missing a required key), Pydantic raises a validation error immediately.
