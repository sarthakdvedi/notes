## 3. Demystifying System Roles

### 3.1 What is the `system` Role?

The API expects a list of message objects. Each object contains a `role` and `content`.

- **`user`:** Messages sent by the end-user (e.g., questions, instructions, input data).
    
- **`assistant`:** Responses generated by the LLM.
    
- **`system`:** High-priority instructions provided _before_ user input to set the LLM's persona, operational rules, constraints, or boundary conditions for the conversation.
    

### 3.2 Key Conceptual Analogy

Sending a message like `"I love you"` produces drastically different outcomes depending on _who_ you say it to:

- To a partner (`system` = Girlfriend) $\rightarrow$ Returns a romantic response.
    
- To a superior (`system` = Strict Workplace Manager) $\rightarrow$ Returns a formal reprimand regarding workplace policy.
    

### 3.3 Real-World Enterprise Application

In enterprise environments, a single base model (e.g., Llama 3) can be instantiated into specialized AI agents by altering the system prompt:

- **System Prompt A:** `"You are a Senior System Architect..."` $\rightarrow$ Evaluates solutions for scalability, security, and partition tolerance.
    
- **System Prompt B:** `"You are a Junior Developer..."` $\rightarrow$ Focuses on immediate syntax fixes and array index handling.

## 4. Understanding `temperature`

### 4.1 What is `temperature`?

`temperature` is a hyperparameter passed during the API call that controls the randomness and creativity of the model's token predictions.

- **LLMs are Prediction Engines:** LLMs do not fetch static facts like a database search; they predict the most probable next token based on training data.
    
- **Value Range:** Typically ranges from `0.0` to `2.0` (values above `2.0` cause API errors or gibberish outputs).
    

### 4.2 Temperature Scale & Behavior

- **`temperature = 0.0` (Deterministic / Low Randomness):**
    
    - Selects the highest probability tokens.
        
    - Produces consistent, predictable, factual, and safe responses.
        
    - _Example (Food Brand Name):_ Returns conventional names like `"Saver"`.
        
- **`temperature = 1.0` (Balanced Creativity):**
    
    - Introduces variation and creative phrasing while maintaining logical cohesion.
        
    - _Example (Food Brand Name):_ Returns coined names like `"Testio"`.
        
- **`temperature = 2.0` (High Randomness / Unconventional):**
    
    - Selects lower probability tokens, leading to unexpected, abstract, or highly creative outputs.
        
    - _Example (Food Brand Name):_ Returns abstract names like `"Swiggy"`.

## 1. System Role

_System Role = Defines the identity, instructions, and behavioral boundaries of the LLM before user input._

Plaintext

```
System Prompt Instructions
       ↓
Base Model Persona Configured
       ↓
User Input Processed
       ↓
Role-Specific Response Generated
```

- `system` → Configures the model's identity, tone, and operational rules.
    
- `user` → Contains the actual prompt or query from the end-user.
    
- `assistant` → Stores prior model completions to maintain multi-turn chat memory.
    

## 2. Temperature

_Temperature = Hyperparameter controlling token prediction randomness and creative variance._

Plaintext

```
Temperature = 0.0 (Deterministic / Safe Choices)
       ↓
Temperature = 1.0 (Balanced Creativity)
       ↓
Temperature = 2.0 (High Randomness / Unconventional)
```

- Scale → Ranges strictly from `0.0` to `2.0`.
    
- Low Values (`0.0 - 0.2`) → Forces highest-probability token selection; ideal for factual, legal, or coding tasks.
    
- High Values (`1.0 - 2.0`) → Selects lower-probability tokens; ideal for creative writing, naming, or brainstorming.
    

## 3. Difference

|**System Role**|**Temperature**|
|---|---|
|Configures model identity & role|Configures output randomness & creativity|
|Answers "Who is the model?"|Answers "How predictable is the response?"|
|Accepts text instructions|Accepts numeric values (`0.0 - 2.0`)|

## 4. Code

```Python
import os
from dotenv import load_dotenv
from groq import Groq

load_dotenv()

my_api_key = os.getenv("GROQ_API_KEY")
if not my_api_key:
    raise ValueError("API key missing!")

client = Groq(api_key=my_api_key)

message_system = {
    "role": "system",
    "content": "You are a brand manager who suggests short, creative names for a brand."
}

message_user = {
    "role": "user",
    "content": "Suggest 1 unique name for my clothing brand."
}

messages = [message_system, message_user]

response = client.chat.completions.create(
    model="llama-3.3-70b-versatile",
    messages=messages,
    temperature=0.0
)

answer = response.choices[0].message.content
print(answer)
```
