# ReAct Framework (Reasoning + Action) in AI Agents

## 1. What is ReAct and Why is it Needed?

- **Definition:** ReAct stands for **Reasoning + Action**. It is a core design pattern used in modern AI development to bridge the gap between standard Large Language Models (LLMs) and full-fledged AI Agents.
    
      
    
- **The Core Problem with Standard LLMs:**
    
      
    - LLMs are trained on historical static data (up to a specific cutoff date).
        
          
        
    - Standard LLMs cannot directly answer real-time, present-day queries (e.g., today's live temperature, present hotel/flight prices, live news, or real-time order tracking).
        
          
        
- **The First Solution (Adding Tools):**
    
      
    - Developers gave LLMs access to external **Tools / APIs** (e.g., weather API, flight search API, calculator, database lookup).
        
          
        
    - However, having multiple tools creates a new challenge: **Which tool should be called, when, in what order, and how many times?**
        
          
        
- **Why Hardcoded `if-else` Logic Fails:**
    
      
    - Real-world user prompts are written in natural language with endless variations and permutations.
        
          
        
    - Deterministic conditional logic (`if-else`) cannot handle complex, dynamic multi-step workflows.
        
          
        

---

## 2. The ReAct Loop Mechanism

ReAct allows the LLM itself to dynamically decide which tool to call, evaluate the result, and decide the next step in an iterative loop until the query is completely answered.

  

### Step-by-Step Working of the ReAct Loop

1. **Thought (Reasoning):** The LLM analyzes the user prompt and breaks it down to decide the immediate next sub-goal.
    
      
    
2. **Action (Tool Call):** The LLM selects **one** specific tool from the available tools list and supplies the required arguments.
    
      
    
3. **Observation:** The system executes the tool (runs the function/API) and feeds the output back into the LLM's conversation history as an observation.
    
      
    
4. **Iterate / Finalize:**
    
      
    - The LLM reviews the observation alongside the prior context.
        
          
        
    - If further actions are needed, it formulates a new Thought and Action.
        
          
        
    - If the problem is fully resolved, it outputs the **Final Answer**.

## 3. Key Concepts for Interviews

- **LLM vs. AI Agent:**
    
      
    - **LLM:** A passive text generator that responds based only on prompt context and static pre-training weight memory.
        
          
        
    - **AI Agent:** An autonomous system combining an LLM, reasoning frameworks (like ReAct), external tool access, and dynamic decision-making capabilities.
        
          
        
- **Chaining Tool Outputs:** The output (observation) of one tool call often serves as the input argument for the subsequent tool call (e.g., Tool 1 fetches product price -> Tool 2 uses a calculator with that price).
    
      
    
- **Role of System Prompt in ReAct:**
    
      
    - ReAct is enforced primarily via structured system prompting rather than complex external frameworks.
        
          
        
    - The system prompt must strictly define:
        
          
        1. The list of available tools and their exact input format.
            
              
            
        2. Execution rules (e.g., call only one tool at a time, wait for observation, never guess tool outputs).
            
              
            
        3. Output formatting requirements (e.g., Thought, Action, Final Answer).
            
              
            
- **Memory & Conversation History:** The ReAct loop requires updating the conversation context (`Assistant` role and tool `Observation`) on every step so the model retains memory across loop iterations.
    
      
    
- **Rate-Limiting / API Delays:** Implementing short sleeps or delays between iterative LLM API calls in code prevents reaching model rate limits.
    
      
    
- **Model Quality Impact:** Higher-tier/larger models perform significantly better at structured reasoning, adhering to tool output schemas, and avoiding invalid tool arguments.

## 4. Summary of Code Implementation Logic

1. **Tools Definition:** Standard Python functions created for specific tasks (e.g., `get_product_price`, `calculator`) mapped into a dictionary.
    
      
    
2. **System Prompt Construction:** Instructs the model to think step-by-step, defines tool schemas, provides strict formatting rules (`Thought`, `Action: ToolName[Arg]`), and sets the stopping condition (`Final Answer:`).
    
      
    
3. **Execution Loop:**
    
      
    - Runs up to a maximum allowed step limit (e.g., 5 iterations).
        
          
        
    - Passes current messages to the LLM.
        
          
        
    - Parses the response using regular expressions (Regex) to extract the intended Action and arguments.
        
          
        
    - Runs the corresponding Python function to get the Observation.
        
          
        
    - Appends the Observation back to the messages array (`Assistant` role context).
        
          
        
    - Breaks the loop early as soon as `Final Answer` is detected in the response.
