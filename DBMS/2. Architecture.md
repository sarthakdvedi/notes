## Abstraction -
pehle to abstract kar dia ( like user ko internal level janne ki need nhi h )
fir upar se view level abstraction bhi h ( like logistics department ko only address dikhe, feedback dep ko full details )


- abstraction = interface + implementation
- to implementation m koi bhi change reflect nahi karega interface par

### Physical data independence -
- change in internal level does not reflect at conceptual level
- or
- physical schema change should not affect logical schema

### Logical data independence -
- change in logical level does not reflect at view level
- or
- logical schema change should not affect view schema


---

## Schema -
- schema =  DB design
- types - 
	  1. external schema  ---> ( contains subschema for different view )
	  2. logical schema ( conventionally called as `the DB schema` )
	    - Attributes, relationships, consistency constraints are defined
		- Data model are used to describe design of DB at logical level
	  3. internal schema

- to interact with DB from another language app we use some interfaces - API.
- JAVA - JDBC (transform query from app into actual query of DB )
- C / CPP - ODBC
